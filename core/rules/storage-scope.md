# Storage scope — whose mailbox, whose drive, which household

A connector gives access to an account, not to a household. The account may
belong to one member, be shared, or be a work account that also happens to be
connected. Every skill that reads through a connector stays inside the
household this record describes.

---

## The rules

1. **Know whose account it is.** The profile's *Connected tools* section names
   the member each connected account belongs to. When it does not, ask once
   and offer to store the answer. Never infer it from an email address.
2. **Read another member's account only with that member.** A brief prepared
   for Anna may include what Piotr's mailbox holds only if Piotr connected it
   for this household and the profile says so.
3. **Work accounts stay out.** A mailbox, calendar or drive that belongs to an
   employer is not searched for household papers unless the member asks for
   that one search. Nothing from it is written to the household record without
   being shown first.
4. **One record per household.** An adult child who helps parents with their
   papers keeps the parents' record in a separate folder with its own profile.
   A skill never mixes entries between two records, and says which record it
   is working in when more than one is known.
5. **Shared drives show who can see.** Before filing into a folder in a shared
   drive, check whether people outside the household can open it when the
   connector can tell. Say so if they can.
6. **Stay inside the household folder.** File operations go to the household
   folder and its subfolders. A skill does not read or write elsewhere on the
   machine except the pointer file and files the user names.

## Saying it

> *"Your calendar connection is the work account (ends with @firma.example).
> I will not add household deadlines there. Do you want them in a personal
> calendar instead?"*
